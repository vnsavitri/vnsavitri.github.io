Why CoworkOS, Not Just a Folder

👀 CoworkOS vs a Cowork folder vs a Claude Chat project

Option A
Project in Claude Chat

Custom instructions plus a few uploaded docs, in the browser. Quick to set up and easy to share. But it can't open your local models, can't update its own memory, won't route tasks, and can't run on a schedule or hold the team to one process.

Best for: quick, shared, cloud Q&A.

Option B
Plain Cowork folder

Point Cowork at any folder and it reads your files, runs skills and connects your tools. Powerful, but with no CLAUDE.md or MEMORY.md it forgets between sessions, has no routing, and no governance — every analyst freelances their own way.

Best for: one-off local file work.

Recommended
Option C
CoworkOS (this kit)

Cowork plus persistent memory, your finance context, routing, the governed process and scheduled tasks. It compounds: every session makes the next one sharper, on your real files, done the approved way.

Best for: the recurring finance work that matters.

Memory Routing

Two places memories live. One simple rule.

When you say "remember this" inside a Finance workstation, Claude needs to know where to put it. Here's the routing decision — one test, every time.

Root MEMORY.md

Cross-cutting facts: your entities, fiscal year, reporting currency, key contacts, and anything that applies across two or more workstations. The shared brain for the whole Finance setup.

[Workstation]/MEMORY.md

Workstation-domain facts only — FX rates used in a specific run, budget versions referenced, run logs for governed tasks, and contacts relevant only to that domain.

CLAUDE.md
(root or workstation)

Prescriptive rules — "always", "never", "before doing X do Y." These go in CLAUDE.md, not MEMORY.md. The 🔒 LOCKED governance sections already handle the most important ones.

The golden rule

Never duplicate the same fact across root and a workstation MEMORY.md. If it could plausibly live in both, default to root. One source of truth, no drift.

File 03  ·  Starter Template

voice-principles.md — your writing voice

Copy & customise

Finance comms that sound like you, not a template

Paste 5–8 of your own board commentaries, variance reports, or CFO updates and ask Claude to extract patterns. It'll populate your tone and style sections from your own writing.

Finance audiences hate hedging and vague language. "Revenue declined $2.3M (U) driven by lower APAC volumes" is better than "there were some revenue challenges." Specificity wins every time. 
# Voice Principles

## Tone
- Sound like: [trusted adviser / sharp analyst]
- More formal with: [board / CFO / external]
- Avoid: [hedging / passive voice / imprecise language]

## Finance Writing Style
- Lead with the number, then explain it
- Variance direction: Favourable (F) / Unfavourable (U)
- Always state the period and comparison base
- Use "driven by" not "due to the fact that"
- Governed reports (board, FX, consolidation) follow
  the finance-shared LOCKED format; voice adds polish,
  not structure

## Sentence Style
- Short sentences for exec comms (20 words max)
- Longer for analyst-level detail
- Active voice: "Revenue grew 12% (F)"
  not "Revenue was seen to increase"

## Words to Avoid
- Never: "leverage," "synergise," "going forward"
- Avoid: "it is important to note that"
- No stacked adjectives or vague intensifiers

## Numbers
- Always include units ($, %, bps)
- Spell out millions: "$2.3M" not "2,300,000"
- Variances: always state direction (F) or (U)

## Words I Use
- [Your signature phrases — add them here]
- e.g. "driven by", "favourable mix", "on plan"
Governance  ·  Keeping the team on one process

How the Governance layer actually holds

Writing a rule in CLAUDE.md is a soft guardrail — Claude follows it, but a determined person can still edit the file. Real governance needs two halves: a clear policy, plus a structural lock that lives outside editable text.

Half 1 · The policy

Guardrails in the root CLAUDE.md

The Governance Agent layer, written down. It tells Claude what must be consistent and what stays free.

📌Mandates the approved skill, plugin and model for Budget Modeller, FX & Consolidation and Board Pack Builder.
🚦Routes each governed task through the finance-shared process — no DIY skills, no three ways of doing budgets.
🟢Leaves light-touch work free — email, slides and ad-hoc tasks aren't bound by finance-shared rules.
🛑If asked to go off-process, Claude refuses and flags it rather than quietly complying.
Half 2 · The lock 🔒

So staff can't quietly change it

The bit that makes "can't easily modify" real. The rules live where individuals can't rewrite them on a whim.

🧩Ship governed skills as one central plugin ("finance-shared"). Staff install it, they don't author it — editing a local copy doesn't change the distributed process.
🔒Hold the master CLAUDE.md read-only / centrally-synced (SharePoint or a managed repo). Only Finance leadership has write access.
✍️Change Control clause: locked sections need Head of Finance sign-off. Claude refuses to edit them in-session and points changes to the master.

Phase 02  ·  Workstations

Time to build your first finance workstation.

A workstation is Claude with a specific job — Budget Modeller, Board Pack Builder, FX Consolidation. Pick the one task that costs you the most time every month. That's where you start.

Phase 2 | Workstations

Every workstation has the same four parts

A workstation is just a folder with three files. The four sections inside its CLAUDE.md define how Claude behaves when routing finance work there.

Identity

One paragraph. Who Claude is in this workstation, what routes here, what doesn't. E.g. "Budget Modeller handles variance analysis and scenario planning — board narratives route to Board Pack Builder instead."

Resources

A table mapping reference files to "read when" conditions. Your chart of accounts loads only for modelling tasks; your board pack template loads only for reporting tasks. Context stays efficient.

Workflow

Numbered steps for the primary task. For a Budget Modeller: open data, identify variances, draft commentary, review assumptions, output. Start simple — 5–7 steps — and refine over time.

Editorial Rules

Always opens with "Follow voice-principles.md in 00_Resources." Then adds finance-specific rules — e.g. "Always label variance direction as (F) or (U). Always state the comparison period explicitly."

For governed workstations (Budget Modeller, FX & Consolidation, Board Pack Builder), these four parts sit on top of the finance-shared locked process — the workstation calls the approved skill and can't override it. Light-touch workstations (Email, Presentation) just use the four parts as they like.

Efficiency

Keep your CoworkOS fast and cheap

Rule 01
Constrain the Root

Keep your master CLAUDE.md under 300 lines. Point to external reference files (entity lists, chart of accounts) rather than stuffing everything in one place — this keeps baseline token costs low.

Rule 02
Avoid Duplicated Rules

Never repeat global rules inside local workstations. If the root already says "label variances as (F) or (U)," your Budget Modeller shouldn't restate it. Inheritance is free.

Recommended Default
Rule 03
Default to Sonnet

Sonnet handles 80% of Finance tasks — variance commentary, board narratives, template filling. Reserve Opus exclusively for complex multi-entity consolidations with many interdependent steps.

Haiku for small, lightweight tasks — quick lookups, short summaries, and simple data transforms.

Token efficiency means CoworkOS stays fast. A bloated root file taxes every session — trim it like you'd trim a good board pack.
Straight Talk  ·  Known Gaps

What this doesn't cover yet

Governance done well is friction plus deterrence, not a wall. Here's what it doesn't solve on its own, and what closes each gap.

Gap
It only binds inside CoworkOS
Plain Claude Chat, a phone, or a fresh folder skip every rule here. Close it: make the approved workstation the easiest path, and spot-check finance outputs that didn't come from it.
Gap
A locked rule still rots without an owner
"Head of Finance sign-off" needs teeth. Close it: name a governance owner, require two-person review on changes to the finance-shared skills, and review the lot quarterly.
Gap
Real numbers live on local laptops
CoworkOS folders hold sensitive figures and persist after people leave. Close it: add a device and offboarding step that wipes leavers' folders.
Gap
The data path is assumed, not confirmed
Pre-results and M&A data is the most sensitive we hold. Close it: confirm retention and enterprise terms with the agreement owner before sensitive data goes in.
Bottom line: treat this as a control that needs an owner and the occasional audit, not a one-and-done lock. The operating controls on the Governance slide handle the rest.
Phase 2 Consideration  ·  Shared Team Use

When Finance teams share a folder — or a Slack memory channel

The current model is personal by design. Shared folders and a Slack team memory channel add a fourth tier — and change where some facts should live.

The gap

The personal model breaks with shared folders

If the team shares one CoworkOS root, MEMORY.md becomes a jumble of personal context and team facts — two very different things in one file.

📌Root MEMORY.md is designed for one person. Your role, your preferences, your working context — not the team's agreed FX rate.
🚦Shared folders mix personal + team facts, making both unreliable. Personal context leaks to colleagues; team decisions get overwritten by individuals.

The clean pattern

Keep personal CoworkOS separate. Add a shared layer.

Three adjustments give you team memory without breaking the personal model or duplicating Slack.

🧩One CoworkOS per person. Don't share the root folder. Personal context stays personal — role, preferences, individual working notes.
📄Add a shared team-context.md in 00_Resources/ — owned by the governance owner, read-only for individuals. Holds agreed entity list, current budget versions, standing FX conventions.
✍️Slack = source of truth for team decisions. MEMORY.md stores a pointer, not a copy — e.g. "USD/AUD 0.645 — see #finance-ops 4 Jun 2026." No drift, no duplication.

Governance at a glance, and what we need from you

One shared, approved way to do the finance work that has to be consistent — budgets, FX, consolidation — without slowing down everything else. Here's the shape of it and the handful of calls that are yours.

What's governed
Budget Modeller, FX & Consolidation, Board Pack Builder — all run the same approved finance-shared skill and model. No DIY methods.
What stays free
Email, slides and ad-hoc work — staff use Claude however suits them. Governance only touches what must be consistent.
How it's locked
Rules ship via a central finance-shared plugin and a read-only master file. A local copy can't override them; changes need your sign-off.
Decisions we need from you
1Approve the finance-shared process for budgets, FX and consolidation before it's locked.
2Name a governance owner and a backup who maintain the locked rules.
3Set the sign-off and review cadence — who approves changes, and how often we review.
4Confirm model pinning and the data path with the Anthropic enterprise owner.
Scheduled & Routine Tasks

Set finance routines to run on their own

Cowork can run a saved prompt on a schedule — daily, weekly, or at month-end. Build these once and they fire in the background, dropping dated outputs into your 00_Scheduled/ folder.

Month-end status snapshot

Each month-end, capture which entities and periods are open, draft versus final, and what's still due. Lands in 00_Scheduled/ with the date, so close progress is always visible.

Daily FX rate log

Record the spot rates used each day to MEMORY.md, so every converted number has a dated, auditable source instead of a vague "around 0.65".

Weekly variance watch

Flag any actual-versus-budget variance over your threshold from the latest data drop, with a one-line likely cause where Claude can see one.

Quarterly governance review

Prompt the governance owner to review the locked finance-shared rules and skill versions. Keeps the guardrails current instead of quietly going stale.

Start with the one you do half-asleep every month. The month-end snapshot is the usual first win.

Glossary of Terms

Model The underlying AI engine. Claude comes in three sizes: Sonnet covers 80% of daily work; Opus is for complex, multi-step tasks with many interdependent decisions; Haiku is the fastest and cheapest for lightweight jobs. ⚡ Default to Sonnet. Reaching for Opus reflexively just burns tokens — and slows you down. Most Finance tasks don't need it. Don't be a #TokkenMaxxer. Think of the environment.
Agent An AI model that can take actions — read files, send messages, run tasks — rather than just answer questions. Claude in Cowork mode is an agent.
Workstation A CoworkOS folder dedicated to a specific task type (e.g. Budget Modeller, Board Pack Builder). Has its own rules and memory. Claude auto-routes tasks to the right one.
Governance Agent The layer that sits between your context and your workstations. It mandates the approved skill, plugin and model for governed finance tasks and routes them through the shared process.
Guardrails The 🔒 LOCKED rules in the root CLAUDE.md that say which approved skill/plugin/model each governed task must use. Set centrally; not edited by individuals.
Skill A packaged workflow that gives Claude a specialised capability — creating Excel models, writing Word docs, pulling data. Install once, trigger by name.
Session A single conversation with Claude. Context resets when it ends — which is exactly the problem MEMORY.md solves. Always log assumptions before closing.
MCP Model Context Protocol. The open standard that lets Claude connect to external tools and services — Slack, Jira, email, and so on. Think of it as Claude's plugin API.
Context Window The total amount of information Claude can hold in a single session. Larger context = more Claude knows, but also slower and pricier. Keep your root CLAUDE.md lean.
MCP Server A connector that implements MCP for one specific service. The Slack MCP server is what gives Claude read/write access to your Slack workspace.
Token The unit any LLM uses to measure text in and out. Longer prompts cost more tokens. The reason Sonnet is faster and cheaper than Opus for everyday Finance tasks.
Plugin A bundle of MCP servers and skills packaged together for easy installation. How capabilities are distributed and added to Cowork.
Routine A task set to run automatically on a schedule. "Every month-end, snapshot the reporting period status." Cowork runs these in the background without you having to ask each time.
