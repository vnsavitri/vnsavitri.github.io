01 · TL;DR

It gives your agent a repeatable LinkedIn operating system.

Instead of asking for a generic “viral post”, you install a set of specialised skills. Each skill knows what to ask for, which references to read, what shape the output should take, and when to stop for your approval.

12loadable skills for content, profile, engagement and team advocacy
3publishing tiers: copy-paste, Publora, or your own custom poster
1shared control loop: draft → approval → publish
The useful idea is not “AI writes posts”. It is “a small content workflow becomes reusable, inspectable and safer to run”.

04 · Core loop

One loop keeps content work legible.

01 / INPUTParse

Understand the topic, URL, audience, goal and any constraints.

02 / SHAPEDraft

Read the relevant skill and reference files, then create the requested artefact.

03 / REVIEWApprove

Show a standard approval card with preview, target and character count.

04 / ACTPublish

Only after “yes” does the selected backend post, schedule or hand off.

DESIGN PRINCIPLE

Drafting and acting are separate

You can use nearly all the creative system without granting it publishing credentials.

IMPLEMENTATION DETAIL

The gate is a convention layer

lib/approval.py formats the card. The skills must still stop and wait for an explicit user response.

07 · Optional connectors

Power is added in layers, not required up front.

Tier 0 · Manualzero credentials

Draft, review and copy-paste. Reading skills ask you to provide the post text or comment URLs. Best for first use, privacy-sensitive work or simple publishing.

Read layer · ApifyAPIFY_TOKEN

Fetch post bodies, comments, replies, recent comments, likers and commenters through no-cookie actors. Without a token, the same skills fall back to pasted content.

Write layer · PubloraPUBLORA_API_KEY + LINKEDIN_PLATFORM_ID

Publish or schedule after approval. The bundle deliberately needs both credentials for automatic posting; a half-configured setup stays manual.

Visual layer · PixfaroPIXFARO_TOKEN

Generate illustrations, quote cards and branded overlays. Without the token, the skill drafts an image prompt for you.

Sources: README · Apify · README · Publora · README · Pixfaro
08 · Publishing safety

The system is opinionated about where agency stops.

BEFORE ACTION

Show the draft

Approval cards include the action, full preview, target URL, reaction and character count.

AT ACTION

Wait for an explicit yes

Skills are instructed to stop until the user says “post”, “yes” or provides edits.

AFTER ACTION

Keep a way back

Scheduled or queued posts can be cancelled through Publora before they go live. A live LinkedIn post must be removed on LinkedIn.

# default mode
draft → approval card → copy-paste

# configured mode
draft → approval card → Publora publish / schedule
Sources: approval.py · backend_selector.py

Implementation guide

Start with the smallest useful setup.

You can get value with a clone and an agent. Add credentials only when the manual loop is proven and you know which layer you actually need.

10 · Step 1 / Install

Choose your host, then add the bundle.

For Claude Code or Codex, the plugin route is the cleanest starting point. A local clone is useful when you want to inspect or modify the skills.

codex plugin add linkedin-skills@linkedin-skills

git clone https://github.com/sergebulaev/linkedin-skills.git
cd linkedin-skills

# Any agent that reads SKILL.md
npx skills add sergebulaev/linkedin-skills

11 · Step 2 / Baseline

Run the self-test before connecting anything.

The repository’s self-test checks install health, optional account layers, offline tests, and per-skill coverage. It reports what will work now and what will fall back to copy-paste.

# basic check
python3 scripts/selftest.py

# clean-install check in a temporary directory
python3 scripts/selftest.py --fresh

# inspect local credential wiring without network calls
python3 scripts/check_config.py --offline
✓Python 3.10+ and required packages
✓Skills present and mirrored correctly
✓Optional credentials detected without printing secrets
✓Per-skill fallbacks made visible
Sources: scripts/selftest.py · scripts/check_config.py
12 · Step 3 / Read layer

Add Apify when copy-pasting context becomes the bottleneck.

The read layer is useful for comment drafting, reply handling, hook extraction and engagement analysis. Keep it optional if you prefer to paste the exact content you want the agent to see.

APIFY_TOKEN

What it unlocks

Post bodies, comment threads, your recent comments, and post engagers through the thin client in lib/apify_client.py.

FALLBACK

What happens without it

The skills ask you for pasted text or URLs. Nothing else in the bundle stops working.

# in .env
APIFY_TOKEN=apify_api_your_token_here

# then verify the wiring
python3 scripts/check_config.py
Sources: README · Apify setup · lib/apify_client.py
13 · Step 4 / Write layer

Connect Publora only after you trust the approval loop.

Automatic publishing is deliberately a second step. Start with manual copy-paste, then add Publora once you know the drafts are good and your account connection is correct.

# in .env
PUBLORA_API_KEY=sk_paste_your_key_here
LINKEDIN_PLATFORM_ID=linkedin-paste_your_id_here

# install the small API dependencies
pip install requests python-dotenv

# run a diagnostic
python3 scripts/check_config.py
IMPORTANT

Both values matter

A key without the LinkedIn platform ID leaves the backend in manual mode.

FIRST TEST

Use a cancellable test

Schedule a harmless test post, confirm the returned ID, then cancel it in the Publora dashboard before it goes live.

Sources: README · Publora setup · backend_selector.py
14 · Step 5 / First run

Use a real task with a narrow brief.

Give the agent a topic + audience + outcome.

Example: “Draft a LinkedIn post about shipping AI agents in production for product leaders. Optimise for thoughtful comments, not reach.”

Let it ask for material when the brief is thin.

Use the Interviewer to capture a specific receipt, a dated moment or a position you would defend.

Review the approval card as a product surface.

Check the voice, factual claims, audience fit, sensitive information, target URL and the exact action requested.

Only then say yes.

In manual mode, copy-paste. In Publora mode, confirm the post or schedule response and retain the returned identifier.

16 · Practical playbook

A sensible first week with the repo.

Day 1Install and run self-test. Draft one post manually.
Day 2Interview yourself. Add three concrete stories to the Story Bank.
Day 3Plan a seven-day cadence. Pick one audience and one measurable goal.
Day 4–7Audit, comment, reply and repurpose. Connect Apify or Publora only if the friction is real.
GOOD FIT

Founders, product leaders, recruiters, technical experts and small teams who want a repeatable content practice without handing over publishing judgement.

NOT A MAGIC BUTTON

The bundle cannot manufacture a point of view, verify every claim or guarantee reach. It makes the work easier to repeat and inspect.

17 · Trade-offs

Useful system, with boundaries worth keeping visible.

STRENGTH

Progressive setup

Draft-only mode is useful immediately, so credentials do not become a prerequisite for learning the workflow.

LIMIT

External services add dependency

Apify, Publora and Pixfaro introduce third-party accounts, pricing, failure modes and data-handling decisions.

STRENGTH

Clear separation of concerns

Markdown skills hold behaviour; references hold knowledge; Python wrappers hold integrations.

LIMIT

Some “algorithm” claims need scrutiny

Heuristics, engagement multipliers and detector guidance should be treated as hypotheses to test, not timeless platform laws.

Use it as a workflow scaffold and editorial assistant. Keep judgement, factual accountability and final publishing authority with a person.
Sources: repository SECURITY.md · algorithm heuristics · untrusted content
18 · Takeaways

What to remember.

1Install the bundle for its contracts.
The value is in reusable, specialised behaviours.
2Keep the loop draft-first.
Approval is the line between assistance and publishing agency.
3Invest in voice and story context.
Specific lived material beats more prompt cleverness.
4Add connectors only when friction justifies them.
Start manual; layer in read, write and visual services deliberately.
A good content agent is less like an autopilot and more like a well-designed editorial desk.
