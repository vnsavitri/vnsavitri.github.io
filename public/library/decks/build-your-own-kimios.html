The Problem

Without a system, Kimi forgets you. KimiOS fixes that.

Without Kimi OS

A fresh start every time

Every session begins from zero. Kimi doesn't know your name, your role, your preferences, or what you were working on yesterday. You spend the first few minutes re-explaining context before any real work happens.

Generic tone. No memory. No shortcuts. Repeat yourself constantly.

With Kimi OS

Kimi already knows you

Kimi reads your constitution and memory files at the start of every session. It knows your role, your active projects, your preferences, and how you like to write. You jump straight into the work.

Your voice. Your context. Routes the right tasks to the right workstation automatically.

KimiOS is just a folder on your computer. No external services, no lock-in.

How It Works

Three layers that power KimiOS. One folder to rule them all.

You  —  prompts, questions, and tasks

Global rules, preferences, routing map, and accumulated facts
voice-principles.md + Skills
Your writing voice and installed capabilities
Workstations
Presentation Studio Data Analyst Prototype Builder Email Helper Social Media Agent + yours

Think of each workstation as a sub-agent dedicated to a specific task. It has its own folder with a local KIMIOS.md, MEMORY.md, and Resources subfolder. The global files apply everywhere; the workstation files layer on top.

The Core Files

Three files power the whole system

File 01
IDENTITY.md

The agent's personality and values. Who Kimi is, how it behaves, its boundaries, and enduring identity notes. Every session starts by reading this.

File 02
KIMIOS.md

The global constitution. Tells Kimi your preferences, rules, folder structure, and routing map. Governs tone, behaviour, and which workstation to use.

File 03
voice-principles.md

Your writing voice. Tone, sentence style, words to avoid, signature phrases. Kimi reads this before writing any content on your behalf.

These four files live in your KimiOS root folder alongside a 00_Resources/ folder. That's the whole system.

- Read vault memory (about_user.md) at start
- Read PROJECT_MEMORY.md at start

- Write to PROJECT_MEMORY.md for global/personal context
- Write to workstation MEMORY.md for domain-specific context

File 03  ·  Starter Template

voice-principles.md — your writing voice

Copy & customise

Makes Kimi sound like you, not a press release

Paste 5–8 of your own emails or messages and ask Kimi to extract patterns from them. It'll fill in the signature phrases and tone sections automatically.

The more specific you are about what to avoid, the better. "No em dashes" and "never say leverage" are more useful than "be casual." 
# Voice Principles

## Tone
- Sound like: [smart peer / trusted advisor / warm colleague]
- More formal with: [senior leaders / new contacts]
- Avoid sounding: [corporate / over-hedged / AI-flavoured]

## Sentence Style
- Vary length — mix short punchy beats with longer ones
- Use contractions: [yes / no]
- Front-load context, then the ask

## Words to Avoid
- Never: "leverage," "synergise," "deep dive"
- No em dashes (use commas or parentheses instead)
- No "I hope this email finds you well" openers
- No stacked adjectives ("incredibly valuable")

## Words I Use
- [Your signature phrases — add them here]
- e.g. "heaps", "nerd out", "level up", "if helpful"

## Formatting
- Short paragraphs (1–2 sentences max)
- Bold sparingly — key terms and names only
- [Other formatting preferences]
Phase 02  ·  Workstations

Time to build your first workstation.

A workstation is Kimi with a specific job — its own rules, its own memory, its own lane. Pick the one recurring task that eats most of your week. That's where you start.

Phase 2 | Workstations

Every workstation has the same four parts

A workstation is just a folder with three files. The four sections inside its KIMIOS.md define how Kimi behaves when it's routing work there.

Identity

One paragraph. Who Kimi is in this workstation, what kinds of tasks route here, and — just as importantly — what doesn't belong here and should go elsewhere.

Resources

A table mapping reference files to "read when" conditions. Kimi only loads these files when the trigger is met, keeping context efficient.

Workflow

Numbered steps for the primary task in this workstation. Keep it simple — 5–7 steps. You'll refine it over time as you see what Kimi gets right and wrong.

Editorial Rules

Always opens with "Follow voice-principles.md in 00_Resources." Then adds domain-specific rules on top — tone calibration, vocabulary, output formats for this specific domain.

Phase 3 | System Maintenance

KimiOS only gets smarter if you save what you learn

End of every task

Insights vanish when the session closes

Preferences you mentioned, decisions you made, context Kimi picked up on — none of it survives unless it's written to the right memory file. Kimi resets completely when the session ends.

Workstation-specific context goes to the workstation's MEMORY.md. Global or personal context goes to root PROJECT_MEMORY.md. One prompt at the end of every task fixes this permanently.

Done consistently, this is what turns KimiOS into a system that compounds — every session makes the next one sharper, in every workstation.

Efficiency

Keep your KimiOS fast and cheap

Rule 1
Constrain the Root

Keep your master KIMIOS.md under 300 lines. Point to external resource files rather than stuffing everything in one place — this keeps baseline token costs low every single session.

Rule 2
Avoid Duplicated Rules

Never repeat global rules inside local workstations. If the root already says "no corporate jargon," your Report Writer workstation shouldn't waste tokens restating it. Inheritance is free.

Recommended Default
Rule 3
Prefer Subagents for Complex Work

Kimi Work has a Subagent tool for non-trivial tasks. Delegate to coder, explore, or plan subagents instead of doing everything inline. They're faster and keep your context window clean.

Use PythonRun for immediate charts and analysis. Use Cron for recurring tasks, not one-offs.

Token efficiency means KimiOS stays fast. A bloated root file taxes every session — trim it like you'd trim a good document.

Reference

Glossary of Terms

Model The underlying AI engine. Kimi 1.5 covers 80% of daily work; escalate to larger models only for complex multi-step tasks with many interdependent decisions. ⚡ Default to the standard model. Reaching for the largest model reflexively just burns tokens — and slows you down. Don't be a #TokkenMaxxer.
Agent An AI model that can take actions — read files, send messages, run tasks — rather than just answer questions. Kimi in Work mode is an agent.
Workstation A KimiOS folder dedicated to a specific task type. Has its own rules, memory, and resources. Kimi auto-routes tasks to the right one based on your routing map.
Skill A packaged workflow that gives Kimi a specialised capability — creating decks, writing Word docs, pulling data. Install once, trigger by name.
Session A single conversation with Kimi. Context resets when it ends — which is exactly the problem PROJECT_MEMORY.md solves.
Plugin A bundle of tools and skills packaged together for easy installation. How capabilities are distributed and added to Kimi Work.
Context Window The total amount of information Kimi can hold in a single session — your instructions, files, and conversation history. Bigger context = more Kimi knows, but also slower.
Subagent A delegated task run via the Agent tool. Three types: coder (general engineering), explore (fast read-only exploration), plan (architecture design). Keeps context clean.
Vault Memory Kimi's built-in persistent user profile assembled at every session start. KimiOS supplements this with PROJECT_MEMORY.md for active project context.
Token The unit any LLM uses to measure text in and out. Longer prompts cost more tokens. The reason concise root files and subagents matter for speed.
Cron A scheduled job in Kimi Work. Runs local-conversation tasks automatically on a recurring, one-time, or manual trigger. Set once, forget.
PythonRun Immediate execution in Daimon's managed Python runtime. Charts, data analysis, file generation — one-shot, right now, no setup needed.
