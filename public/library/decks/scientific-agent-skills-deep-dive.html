The beginner version

Working code isn’t the same as defensible science.

Scientific Agent Skills are small, reviewable procedures that tell an agent how a field expects a task to be done.

Without a skillRisk

An agent can produce plausible code while missing a convention that changes the meaning of the result.

With a skillGuardrail

The agent gets explicit guidance about the test, identifier namespace, assumptions and caveats that matter.

Paper: the introduction frames the problem as procedural knowledge, not just code generation. Read the paper, pp. 1–2
The central distinction

“An agent can return working code. A defensible analysis depends on the procedural choices behind it.

Example: RNA-seq

A script may run while treating 100 cells from each of three mice as 300 independent replicates. The skill makes the experimental unit explicit: n = 3 mice, not n = 300 cells.

Example: file coordinates

A pipeline may shift genomic intervals by one base if coordinate conventions are left implicit. A skill turns that convention into a check the agent can follow.

Paper: concrete failure examples and the procedural framing. pp. 1–2
Why it is useful

It packages hard-won judgement into something an agent can load when needed.

Faster starts

Skip repeated package and API discovery when a documented workflow already exists.

Better boundaries

Make validation, provenance and safety limits part of the workflow rather than a late reminder.

Reusable practice

Turn a successful research procedure into a portable, inspectable unit that other harnesses can discover.

Deep dive · 01

A skill is a directory, not a magical plugin.

At minimum, it has a human-readable SKILL.md. It may also carry references, scripts and assets.

skills/your-skill/
├── SKILL.md # required
├── references/ # deeper docs
├── scripts/ # runnable helpers
└── assets/ # templates / static files
FrontmatterRouting

Name, description, licence, compatibility, allowed tools and metadata.

Instruction bodyProcedure

When to use it, what to do, what to check and what not to claim.

Supporting filesDepth

Reference material and code stay deferred until the workflow needs them.

Deep dive · 03

One research task can compose several kinds of skill.

The library’s worked examples show a pattern: domain skills do the specialised work, while statistics and communication skills connect the workflow into something interpretable.

01 · DOMAIN

Find and transform

Retrieve data, resolve identifiers, use a package or query a named scientific resource.

02 · METHOD

Analyse and check

Apply the appropriate test, assumptions, uncertainty treatment or experimental convention.

03 · COMMUNICATE

Report and trace

Generate figures, explain caveats and return evidence with a provenance trail.

Useful mental model

Skills are not a single giant “scientist prompt”. They are composable procedures with different jobs.

Paper: 46 documented workflows, median of 4 categories per example; communication and statistics act as connective tissue. Paper · Section 3

Deep dive · 06 · evidence boundary

Useful evidence, modest claim.

What the paper supports

  • The repository has a tiered documentation design.
  • The pinned corpus fits better when references stay deferred.
  • Descriptions are a routing bottleneck worth measuring.
  • The library is a structured, portable knowledge artefact.

What it does not establish

  • That skills improve scientific outcomes on real tasks.
  • That a host selects the right skill reliably.
  • That every skill is substantively correct or current.
  • That portability means identical behaviour across hosts.
Practical consequence

Adopt it as a strong starting point, then evaluate the specific skills and workflows that matter to your own research agenda.

Paper: limitations cover task-level evaluation, selection, review coverage, host portability and the moving snapshot. Paper · Section 6

Deep dive · 08 · security

Skills are executable instructions. Treat them like code with influence.

Repository warningDo not skip

Skills can instruct an agent to run code, install packages, make network requests and modify files. Review what you install.

Community contributions may have uneven review coverage.

1 · Narrow the install

Start with skills relevant to the project, not the whole library.

2 · Read the SKILL.md

Understand dependencies, tools, credentials and external services.

3 · Pin the release

Record the repository tag, skill name and metadata version used.

4 · Scan before trust

Run the recommended scanner and inspect behaviour in your environment.

Start with a narrow research loop.

Evaluate the path

Recommended first experiment

Use one workflow from your PhD research agenda, such as evidence-traceable literature synthesis, and compare an agent with and without the selected skills.

How-to guide · 02 · scope

Don’t start with all 166.

Choose the smallest collection that covers your first workflow. This reduces standing context and the number of routing candidates.

gh skill install K-Dense-AI/scientific-agent-skills scanpy

# pin a release for reproducibility
gh skill install K-Dense-AI/scientific-agent-skills \

How-to guide · 06 · first invocation

Ask the agent to expose the procedure, not just the answer.

Use the available scientific skills for this task.

Workflow: evidence-traceable literature synthesis
Domain: bio-AI convergence
Requirements:
  1. Name the skills you selected and why.
  2. State assumptions and missing data.
  3. Keep claims tied to source passages.
  4. Separate findings, inference and recommendation.
  5. Save a provenance log and an uncertainty note.
  6. Stop before clinical or regulatory decisions.

How-to guide · 07 · validation

Evaluate the harness, the skill and the scientific result separately.

Layer 1Selection

Did it choose well?

Create labelled tasks that name the intended skill and close neighbours. Measure correct selection and unnecessary loading.

Layer 2Execution

Did it follow the procedure?

Check tool calls, assumptions, reference loading, script use and stopping behaviour against a rubric.

Layer 3Outcome

Did the science hold?

Score against domain answer keys, published conventions, provenance completeness and expert review.

# minimum golden-set record
task_id: literature-001
intended_skill: paper-lookup
must_cite: true
must_state_limits: true
forbidden: patient-specific advice
review: domain-expert + provenance-check
Paper explicitly calls for controlled task-level evaluations and says its corpus measurements do not establish benefit. The golden-set design above is a practical extension. Paper · Limitations

One-sentence takeaway

Skills don’t turn an agent into a scientist by themselves. They give it a better procedural memory, which you still need to test, constrain and review.
