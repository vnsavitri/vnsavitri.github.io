A deep dive into Litho, the Rust CLI formerly known as deepwiki-rs. It analyses a repository, asks specialised agents to make sense of it, and writes a structured C4 documentation set.

The README describes a four-stage pipeline: preprocessing → research → composition → verification/output · README.md02 / TL;DR

Documentation decays. Code keeps moving.

Litho is designed for the awkward gap between what a codebase does and what the team can still explain.

The payoff is not “more docs”. It’s less archaeology.

New teammates find the shape of the system sooner. Reviewers get architectural context. Maintainers get a repeatable baseline that can be regenerated after change.

Without a generator

  • Important context lives in people’s heads.
  • Manual diagrams drift away from implementation.
  • Every onboarding question becomes a bespoke tour.

With Litho in the loop

  • Repository structure becomes a shared starting point.
  • C4 views give the team a common abstraction ladder.
  • Cacheable, repeatable passes make refreshes cheaper.
Benefits are stated by the project as onboarding, code review, compliance, multi-language support, and CI/CD suitability · README.md03 / WHY

Where it earns its keep

Use Litho when the cost of understanding a system is higher than the cost of generating a first architectural map.

GOOD FIT / NOT A RUNTIME OBSERVER

It is a read-only analysis and documentation tool. It doesn’t replace design judgement, tests, production observability, or human review.

Every agent signs a small contract.

The StepForwardAgent trait turns each analysis pass into a repeatable unit: declare inputs, build a prompt, choose an execution mode, validate the output, and store the result.

DATArequired and optional sources from memory, research, or local knowledge
MODEstructured extraction, free-form prompting, or prompting with tools
FORMATtoken-aware project structure, insights, dependencies, README material
RESULTtyped output, formatted summary, and a memory write

Structured output

The agent asks the provider for a typed result that can be deserialised against a JSON schema. This is useful when the next stage depends on predictable fields.

One useful finishing move

After writing the Markdown, Litho invokes mermaid-fixer to detect and repair generated Mermaid syntax. That dependency is checked at startup, so a missing fixer stops the run early.

This is a good example of a generator treating its own output as something to validate, not just something to emit.

Configure the decisions, not the noise.

Start with the example TOML. The high-impact choices are provider, endpoint, model pairing, concurrency, target language, cache, and local knowledge.

[llm]
provider = "ollama"
api_base_url = "http://localhost:11434"
model_efficient = "your-fast-model"
model_powerful = "your-strong-model"

[cache]
enabled = true
expire_hours = 24

target_language = "en"

Cloud or local?

Use a compatible hosted endpoint for stronger models, or Ollama where local inference and data locality matter more.

Fast model or strong model?

Keep routine extraction efficient, then reserve the powerful model for complex reasoning and fallback.

Fresh run or cache-assisted run?

Use the cache while iterating. Use --force-regenerate when you need to invalidate prior LLM responses.

Code only or code + knowledge?

Mount ADRs, architecture docs, SQL, API specs, and business context when code alone can’t explain intent.

Give the agents the context code can’t contain.

Local knowledge integration lets you classify and chunk supporting documents, cache them, and route relevant categories to selected agents.

Good candidates: ADRs, API contracts, database schemas, deployment notes, workflows, and domain glossaries.
[knowledge.local_docs]
enabled = true
cache_dir = ".litho/cache/knowledge"

[[categories]]
name = "architecture"
paths = [
"docs/architecture/**/*.md",
"docs/design/**/*.pdf"
]
target_agents = [
"ArchitectureResearcher",
"ArchitectureEditor"
]
deepwiki-rs sync-knowledge --force

Strength

Strength

Strength

Watch

Architecture roles and relationships can be plausible but wrong. Cross-check consequential claims.

Watch

The short version.

Litho is a focused, local-first-feeling architecture documentation engine. Its value comes from the workflow around the model: inspectable phases, typed hand-offs, scoped memory, caching, and output repair.
