01 / START HERE

The short version, before the plumbing.

Rowboat is trying to solve a simple but stubborn problem: your AI knows your work, but your team can’t collaborate with that context without handing it to a shared bot.

TL;DRBEGINNER VIEW

Every teammate gets their own assistant. The team shares the room.

Your Rowboat reads the context you choose on your machine, acts through your tools, and posts only the result you decide to bring into the Space.
The idea

Private by default

Email, meetings, notes, code and model keys stay with the person who owns them.

The shared layer

One Space

Messages, files, threads, reactions, polls and whiteboards live in a common collaboration surface.

The bridge

@rowboat

Mention your own agent. It gathers private context locally, then acts as you in the room.

Source: README · Spaces: the multiplayer part

WHY IT MATTERSTHE PAIN

Most team AI starts with a compromise.

01
Single-player context

One person has to paste the background into a chat, or the assistant sees only a thin slice of the work.

02
Shared bot exposure

A central assistant becomes the easiest place to connect everyone’s inboxes, notes and private history.

03
Memory that doesn’t compound

Important relationships and decisions remain trapped in separate transcripts and tools.

Rowboat’s bet is that collaboration should happen around explicit shared artefacts, while personal context remains personal.Interpretation of the repo’s “local-first” and Spaces design
Important nuance: “Private by default” doesn’t mean “nothing leaves your machine”. It means the boundary is explicit: what gets posted to a Space is visible to the team.
BENEFITSWHAT IT UNLOCKS

Useful when the work is contextual, collaborative and messy.

Faster hand-offs

Ask your agent to turn your meeting context into a proposal, then let the team review the same file in the Space.

Living project memory

Keep decisions, files, threads and history together rather than relying on a static wiki or a lost chat transcript.

Many agents, one substrate

Claude Code, Codex or another MCP-capable agent can operate through the same Space surface with member attribution.

Inspectable work

Files are Markdown, history has diffs and restore, and the shared layer is open source and self-hostable.

Examples are grounded in the repo’s documented flows: meeting notes → proposal, review → implementation, local knowledge graph, code mode and MCP extensions.

The important design choice is the boundary.

Rowboat is not just a desktop chat client. The repo is a collaboration system with a local assistant on one side and Harbor, a shared server, on the other.

SPACE ANATOMYSHARED WORK

A Space is a channel plus a shared folder.

Conversation

Messages & threads

Topics, DMs, reactions, polls, mentions, read state and activity all ride the same collaboration substrate.

Artefacts

Markdown & whiteboards

Files are versioned, diffable and restorable. A whiteboard is treated as an asset with ephemeral relay frames.

Coordination

Invites & attribution

Invite binding, member identity and “Name (via agent)” receipts make authorship visible in the room.

The collaboration primitive is not the bot. It’s the shared, inspectable state that people and agents can both read and change.

DATA MODELEVENTS, HISTORY, CONFLICTS

Shared work is a log with projections, not a magic document.

01 / READRead current versionAgents receive content, version and recent history.
02 / PROPOSESend base versionEvery agent change carries a reason and its base.
03 / MERGEThree-way mergeNon-overlapping edits merge. Collisions return as normal outcomes.
04 / RESUMEReplay by offsetWebSocket subscribers catch up after a disconnect.
Implemented

History is first-class

Change-sets, diffs, restore, event offsets and golden merge fixtures make the collaboration state inspectable.

Implemented

Conflicts are not failures

A stale base returns current content, colliding regions and recent history so a well-behaved agent can retry.

TRUST BOUNDARYPRIVACY + AUTH

Local-first is a product rule, not just a storage choice.

Private

Read only what the task needs

The repo explicitly warns agents not to pull a whole HR directory just to message one member.

Shared

Answer only what was asked

Private emails, DMs and notes should not leak into the shared reply as incidental context.

Auditable

Receipts describe action

The room sees what the agent did, not every private source it read to do it.

OAuth is the production boundary; dev tokens are explicitly for local development and tests only. Never expose dev auth publicly.

Source: README · privacy rules and CONTRACT.md · auth.

READ THE SIGNALEVIDENCE + LIMITS

Promising architecture. Still a moving target.

Evidence

Repo + tests

The repository includes protocol schemas, golden merge fixtures, API tests, MCP parity tests, WebSocket tests and a “day in the life” integration suite.

Interpretation

Strongest differentiator

The most interesting design move is not “AI in a team chat”. It is explicit sharing between multiple personal agents.

Decision point

Use it where context matters

It is a better fit for agentic project work than for a simple FAQ bot or a central inbox summariser.

!
Not production maturity by default

Protocol v0, active dogfooding and explicit deferred features mean you need to pin versions and expect change.

!
Privacy still depends on behaviour

A local boundary reduces exposure, but a careless prompt can still post sensitive content into a shared Space.

If you adopt Rowboat, treat the shared Space as a governed collaboration surface, not as a private notebook with a nicer UI.Recommendation for implementation
03 / HOW TO IMPLEMENT

Get one useful loop working before you build a platform.

The fastest path is: install the desktop assistant, create one Space, post one shared artefact, then connect an MCP-capable agent to review or implement it.

QUICK STARTBEGINNER PATH

Start with the smallest useful loop.

01 / INSTALLDownload RowboatUse the Mac, Windows or Linux build from the official downloads page.
02 / CONNECTChoose contextConnect only the email, calendar, notes, browser and model provider you actually need.
03 / CREATEOpen a SpaceInvite one collaborator. Put a real work artefact in the shared folder.
04 / PROVEAsk @rowboatUse one scoped prompt and check the receipt, file history and attribution.
Validation checkpoint: if you can explain what context was private, what entered the Space, and what changed in the file history, your first loop is working.

Download link: rowboatlabs.com/downloads

ROLLOUTDONE WHEN…

A sensible first-week rollout has five proof points.

01

One real Space

At least one human collaborator can find the shared files and understand the room.

02

One local source

The agent can use a bounded personal context source without needing a shared inbox.

03

One agent action

A scoped prompt produces a visible, attributable result in the Space.

04

One merge conflict

The team has seen how a stale change returns current content and how to retry safely.

05

One privacy rule

Everyone can state what stays local, what can be posted, and who reviews the receipt.

Next

Then scale the substrate

Only after the loop works should you add Postgres, OIDC, deployment routing or more agents.

TAKEAWAYSTHE LAST SLIDE

Rowboat’s real product idea is a social contract for agents.

Private context compounds on each person’s machine. Shared work becomes useful when the boundary is explicit, the artefacts are inspectable, and every agent action has a human owner.
Remember

Personal agents

Each person brings their own memory, tools and model keys.

Remember

Shared artefacts

Remember

Read narrowly. Post deliberately. Review what changed.
