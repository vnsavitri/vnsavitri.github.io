The Problem

Without a system, Cowork forgets you. CoworkOS fixes that.

Without Cowork OS

A fresh start every time

Every session begins from zero. Claude doesn't know your name, your role, your preferences, or what you were working on yesterday. You spend the first few minutes re-explaining context before any real work happens.

Generic tone. No memory. No shortcuts. Repeat yourself constantly.

With Cowork OS

Claude already knows you

Claude reads your constitution and memory files at the start of every session. It knows your role, your active projects, your preferences, and how you like to write. You jump straight into the work.

Your voice. Your context. Routes the right tasks to the right workstation automatically.

CoworkOS is just a folder on your computer. No external services, no lock-in.

How It Works

Three layers that power CoworkOS. One folder to rule them all.

You  —  prompts, questions, and tasks
CoworkOS
CLAUDE.md + MEMORY.md
Global rules, preferences, routing map, and accumulated facts
voice-principles.md + Skills
Your writing voice and installed capabilities
Workstations
Email HQ Presso Station Data Scientist UX Researcher Slack Buddy + yours

Think of each workstation as a sub-agent dedicated to a specific task. It has its own folder with a local CLAUDE.md, MEMORY.md, and Resources subfolder. The global files apply everywhere; the workstation files layer on top.

The Core Files

Three files power the whole system

File 01
CLAUDE.md

The global constitution. Tells Claude your preferences, rules, folder structure, and routing map. Every session starts by reading this.

File 02
MEMORY.md

The persistent brain. Claude reads it at session start and writes to it when you say "remember this." It builds up your context over time.

File 03
voice-principles.md

Your writing voice. Tone, sentence style, words to avoid, signature phrases. Claude reads this before writing any content on your behalf.

These three files live in your CoworkOS root folder alongside a 00_Resources/ folder. That's the whole system.

File 02  ·  Memory Routing

Two places memories live. One simple rule.

Every workstation has its own MEMORY.md. Knowing which one to write to keeps things clean — and stops your root file from bloating.

Root MEMORY.md

Cross-cutting facts that apply everywhere — your role, key people, active projects, toolchain, personal preferences. If it would be useful in three different workstations, it lives here.

[Workstation]/MEMORY.md

Domain-specific facts only relevant inside that workstation — contacts for that domain, build decisions, output paths, tool configs. If it only matters when you're doing that specific type of work, it goes here.

CLAUDE.md (root or workstation)

Behavioral rules — anything prescriptive: "always read voice-principles.md," "never start with a subject line," "before drafting, check for an existing thread." Rules belong in CLAUDE.md, not MEMORY.md.

The golden rule

When in doubt, write to root MEMORY.md. Never duplicate the same fact across both files. If a memory could plausibly live in either place, root wins — it's always in scope regardless of which workstation you're in.

File 03  ·  Starter Template

voice-principles.md — your writing voice

Copy & customise

Makes Claude sound like you, not a press release

Paste 5–8 of your own emails or Slack messages and ask Claude to extract patterns from them. It'll fill in the signature phrases and tone sections automatically.

The more specific you are about what to avoid, the better. "No em dashes" and "never say leverage" are more useful than "be casual." 
# Voice Principles

## Tone
- Sound like: [smart peer / trusted advisor / warm colleague]
- More formal with: [senior leaders / new contacts]

## Sentence Style
- Vary length — mix short punchy beats with longer ones
- Use contractions: [yes / no]

- Never: "leverage," "synergise," "deep dive," "circle back"
- No em dashes (use commas or parentheses instead)
- No "I hope this email finds you well" openers

Phase 02  ·  Workstations

Time to build your first workstation.

A workstation is Claude with a specific job — its own rules, its own memory, its own lane. Pick the one recurring task that eats most of your week. That's where you start.

Phase 2 | Workstations

Every workstation has the same four parts

A workstation is just a folder with three files. The four sections inside its CLAUDE.md define how Claude behaves when it's routing work there.

Identity

One paragraph. Who Claude is in this workstation, what kinds of tasks route here, and — just as importantly — what doesn't belong here and should go elsewhere.

Resources

A table mapping reference files to "read when" conditions. Claude only loads these files when the trigger is met, keeping context efficient.

Workflow

Numbered steps for the primary task in this workstation. Keep it simple — 5–7 steps. You'll refine it over time as you see what Claude gets right and wrong.

Editorial Rules

Always opens with "Follow voice-principles.md in 00_Resources." Then adds domain-specific rules on top — tone calibration, vocabulary, output formats for this specific domain.

Efficiency

Keep your CoworkOS fast and cheap

Rule 1
Constrain the Root

Keep your master CLAUDE.md under 300 lines. Point to external resource files rather than stuffing everything in one place — this keeps baseline token costs low every single session.

Rule 2
Avoid Duplicated Rules

Never repeat global rules inside local workstations. If the root already says "no corporate jargon," your Email HQ workstation shouldn't waste tokens restating it. Inheritance is free.

Recommended Default
Rule 3
Default to Sonnet 5

Sonnet 5 handles 80% of daily tasks — it's faster and cheaper. Reserve Opus 5 for complex workflows with three or more interdependent steps.

Haiku 4.5 for small, lightweight tasks; Fable 5 only for long-horizon autonomous agents. See the model slide for the full picture.

Token efficiency means CoworkOS stays fast. A bloated root file taxes every session — trim it like you'd trim a good document.

Reference

Glossary of Terms

Model The underlying AI engine. Claude's current lineup: Haiku 4.5 is fastest and cheapest for lightweight jobs; Sonnet 5 covers ~80% of daily work; Opus 5 is for complex, multi-step tasks with many interdependent decisions; Fable 5 is the Mythos-class model above Opus, reserved for long-horizon autonomous agent runs. ⚡ Default to Sonnet 5. Reaching for Opus (or Fable) reflexively just burns tokens — and slows you down. Most tasks don't need it. Don't be a #TokkenMaxxer. Think of the environment.
Agent An AI model that can take actions — read files, send messages, run tasks — rather than just answer questions. Claude in Cowork mode is an agent.
Workstation A CoworkOS folder dedicated to a specific task type. Has its own rules, memory, and resources. Claude auto-routes tasks to the right one based on your routing map.
Skill A packaged workflow that gives Claude a specialised capability — creating decks, writing Word docs, pulling data. Install once, trigger by name.
Session A single conversation with Claude. Context resets when it ends — which is exactly the problem MEMORY.md solves.
MCP Model Context Protocol. The open standard that lets Claude connect to external tools and services — Slack, Jira, email, and so on. Think of it as Claude's plugin API.
Context Window The total amount of information Claude can hold in a single session — your instructions, files, and conversation history. Bigger context = more Claude knows, but also slower and pricier.
MCP Server A connector that implements MCP for one specific service. The Slack MCP server is what gives Claude read/write access to your Slack workspace.
Token The unit any LLM uses to measure text in and out. Longer prompts cost more tokens. The reason Sonnet or Haiku is faster and cheaper than Opus for everyday tasks.
Plugin A bundle of MCP servers and skills packaged together for easy installation. How capabilities are distributed and added to Cowork.
Routine A task set to run automatically on a schedule. "Every morning, summarise my unread Slack." Cowork runs these in the background without you having to ask each time.
